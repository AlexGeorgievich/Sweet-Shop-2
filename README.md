# Sweet Shop — локальная витрина и CRM

Sweet Shop — локальная система для кондитерской. Она объединяет публичную витрину, форму заявки, ИИ-консультанта, Telegram-уведомления и CRM менеджеров. Проект рассчитан на разработку, демонстрации и нагрузочное моделирование на Windows через Docker Desktop.

## Назначение

Система закрывает путь от первого обращения до обработки заказа:

- витрина показывает каталог, ориентировочные цены и фотографии;
- посетитель получает помощь консультанта и может отправить заявку;
- заявка сохраняется в базе данных, получает статус, источник, ответственного и историю изменений;
- менеджер работает с фильтрами, карточками, задачами, комментариями и SLA;
- аналитика показывает воронку, конверсию, выручку, средний чек, товары, источники, дни и часы;
- Telegram отправляет уведомление после сохранения заявки, поэтому сбой Telegram не теряет заказ;
- демонстрационный контур позволяет безопасно проверять CRM на большом наборе синтетических данных.

## Архитектура

```text
site/       Next.js 16 + React 19: витрина, CRM, аналитика, proxy API
backend/    FastAPI + SQLAlchemy async + Alembic: API, auth, CRM, генератор
PostgreSQL  основное хранилище заявок, клиентов, задач, истории и аудита
compose.yml Docker Compose: db, migrate, api, frontend и одноразовые tools
```

Публичные заявки и CRM при включённых флагах `fastapi` работают через PostgreSQL. Legacy JSON-данные остаются локальным источником для импорта и обратной совместимости; папка `site/.data` не попадает в Git.

## Режимы данных

В одной базе доступны два изолированных режима:

- `production` — реальные заявки. Это режим по умолчанию; публичная форма и legacy-импорт пишут только сюда.
- `demo` — синтетические заявки для обучения, демонстраций и проверки аналитики. Доступен только администратору в его текущей сессии.

Переключение одного браузера не меняет режим других сессий. В demo отображается предупреждающая полоса, а генератор заменяет только demo-данные и не вызывает Telegram или LLM.

Эталонный набор `seed=20260831`, `as-of=2026-08-31` содержит 1000 заявок за шесть месяцев, 728 клиентов, 7 сотрудников, связанные задачи, комментарии, историю, аудит и события конверсии. Одинаковые параметры дают одинаковый digest.

## Локальные адреса

- витрина и CRM: <http://localhost:3000>;
- вход в CRM: <http://localhost:3000/crm/login>;
- аналитика: <http://localhost:3000/crm/analytics>;
- API health: <http://localhost:8000/health/ready>;
- Swagger API: <http://localhost:8000/docs>;
- PostgreSQL с хоста: `127.0.0.1:5433`.

Для локального запуска используйте `http://`, а не `https://`: TLS на этих портах не настроен.

## Требования

- Windows 10/11 и Docker Desktop;
- Node.js 22.13+ и npm;
- интернет для первой установки образов и зависимостей, Telegram и LLM Router.

## Быстрый запуск через Docker

1. Перейдите в `Sweet-Shop-main`.
2. Создайте `.env` из `.env.example` и задайте локальные значения. Для PostgreSQL-контура установите `ORDER_BACKEND=fastapi` и `CRM_BACKEND=fastapi`.
3. Запустите сервисы:

```powershell
docker compose up -d --build
docker compose ps
```

4. Создайте администратора (значения берутся из `.env`):

```powershell
docker compose --profile tools run --rm bootstrap-admin
```

5. Откройте <http://localhost:3000> или <http://localhost:3000/crm/login>.

Миграции Alembic выполняются сервисом `migrate` до запуска API. Остановить контейнеры можно командой `docker compose down`.

## Настройка окружения

Docker читает `.env` из корня, standalone frontend — `site/.env.local`. Не публикуйте эти файлы, токены и пароли.

Основные переменные: `POSTGRES_*`, `DATABASE_URL`, `NEXT_PUBLIC_API_BASE_URL`, `API_INTERNAL_URL`, `ORDER_BACKEND`, `CRM_BACKEND`, `APP_ENVIRONMENT`, `APP_VERSION`, `LOGIN_MAX_ATTEMPTS`, `LOGIN_WINDOW_SECONDS`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_FULL_NAME`. Для Telegram и ИИ-консультанта задаются `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_WEBHOOK_SECRET`, `LLM_ROUTER_API_KEY`, `LLM_ROUTER_BASE_URL`, `LLM_ROUTER_MODEL`.

## Публичный заказ

Посетитель выбирает товар, получает подсказку консультанта, при желании запускает колесо подарков и заполняет форму с именем, телефоном, товаром, датой, количеством гостей, пожеланиями и согласием на обработку данных. Консультант может прикрепить краткое резюме диалога. Сумма на сайте ориентировочная; точную стоимость менеджер согласует отдельно.

Заявка сначала записывается локально, затем отправляется уведомление Telegram. Ошибка Telegram не означает потерю заявки.

## CRM и аналитика

CRM поддерживает поиск по номеру, имени, телефону, товару и тексту; фильтры по статусу, товару, источнику и типу клиента; постраничный список; карточку заказа; смену статуса; назначение команды; задачи, комментарии, историю и аудит.

Аналитика пересчитывает выборку по периоду, товару, источнику, статусу, дню недели и часу. Доступны воронка, оплаченные заказы, конверсия, выручка, средний чек, рейтинг товаров, сравнение каналов и тепловая карта обращений.

## Telegram и ИИ-консультант

При заполненных ключах бот запускается из `site`:

```powershell
npm run bot
```

Команды Telegram-бота: `/start`, `/help`, `/reset`. Без сети сайт, CRM и локальная база продолжают работать, но внешние ответы и уведомления недоступны.

## Генерация демоданных

Через CRM откройте `/crm/team`, выберите seed и контрольную дату, затем нажмите «Создать / пересоздать 1000 заявок».

Через CLI:

```powershell
docker compose exec api python -m scripts.seed_demo --count 1000 --seed 20260831 --as-of 2026-08-31
```

Проверка изоляции demo/production и возврата в production:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\smoke-demo.ps1
```

Генератор учитывает связи между товаром, источником, статусом, временем ответа, ответственным, производственными задачами и конверсией. В выборке есть рабочие и проблемные заявки: просроченные SLA, отказы, повторные обращения, неполные данные и задержки производства. Генерация заменяет только `data_mode=demo`, выполняется транзакционно и не вызывает Telegram/LLM.

## Резервное копирование и безопасность

Legacy-заказы хранятся отдельными JSON-файлами в `site/.data/orders/`; для копии остановите сервер и скопируйте эту папку. PostgreSQL хранится в Docker volume `postgres_data`.

Перед не локальным использованием замените пароли, ограничьте публикацию портов, настройте HTTPS, резервное копирование, политику обработки персональных данных и мониторинг. Demo-данные не должны использоваться как реальные заказы.

## Ограничения текущей версии

- цены на витрине ориентировочные, оплата и бухгалтерский учёт не реализованы;
- память Telegram-диалогов хранится в процессе и сбрасывается после перезапуска;
- публичное размещение и production-hardening требуют отдельной настройки;
- автоматическая повторная доставка Telegram пока не реализована.

## Каталог демоверсии
