# Локальная CRM «Сладкая история» — дизайн

## Цель

Надёжно сохранять каждую проверенную заявку до попытки отправки Telegram-уведомления и предоставить локальную служебную страницу `/crm` для поиска, фильтрации и смены статусов заявок.

## Архитектура

- `POST /api/orders` валидирует заявку, создаёт нормализованную запись и атомарно сохраняет её в `.data/orders/<orderId>.json`.
- Только после успешного сохранения сервер вызывает Telegram Bot API. Результат доставки записывается обратно в тот же JSON атомарной заменой файла.
- Ошибка Telegram не отменяет заявку: API возвращает успешное сохранение и признак недоставленного уведомления.
- `GET /api/crm/orders` читает JSON-файлы, сортирует записи по времени создания и возвращает их CRM.
- `PATCH /api/crm/orders` проверяет статус и атомарно обновляет одну запись.
- `/crm` — скрытая от публичной навигации клиентская страница в шоколадно-молочном стиле, работающая с CRM API.

## Модель заявки

Запись содержит: `id`, `createdAt`, `updatedAt`, данные клиента и заказа, `source`, `amountLabel`, `status`, подарок, саммери консультации и объект `telegram` со статусом доставки, временем и последней ошибкой.

Статусы: `new`, `contacted`, `agreement`, `paid`, `rejected`.

## Надёжность

Запись выполняется через временный файл в каталоге заказа и `rename`, чтобы частично записанный JSON не считался заявкой. Имена файлов строятся только из серверного ID. Telegram вызывается после первого успешного сохранения.

## Ограничения демо

CRM предназначена для локального использования и первых десятков заявок. Авторизация, многопользовательские блокировки и внешняя база данных не входят в этот этап. Страница не добавляется в публичное меню.
