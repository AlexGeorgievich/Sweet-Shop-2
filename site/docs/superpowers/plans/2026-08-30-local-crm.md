# Local CRM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist every validated order locally before Telegram delivery and provide a functional `/crm` dashboard with search, filters, and status updates.

**Architecture:** A focused filesystem repository owns atomic JSON persistence under `.data/orders`. Existing order submission calls it before Telegram and records notification outcome afterwards. A CRM API exposes read and status-update operations to a new client page.

**Tech Stack:** Vinext, Next/React 19, TypeScript, Node filesystem API, Node test runner, CSS.

**Spec:** `docs/superpowers/specs/2026-08-30-local-crm-design.md`

## Global Constraints

- Preserve the current public form, consultant, wheel, and Telegram message behavior.
- Store one order per JSON file in `.data/orders` using atomic replacement.
- Never expose environment secrets to the browser or documentation.
- Keep all work local and leave `/crm` out of public navigation.
- Use statuses `new`, `contacted`, `agreement`, `paid`, `rejected`.
